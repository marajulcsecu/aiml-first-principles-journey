অধ্যায় ০.১.১ • আর্কিটেকচার প্রথম

১. AI/ML-এ কেন Python রাজত্ব করে—এবং এর নিচে কীভাবে C/C++ কাজ করে

C, C++ বা Java ব্যাকগ্রাউন্ড থেকে এসে তোমার প্রথম যৌক্তিক ইঞ্জিনিয়ারিং প্রশ্ন হওয়া উচিত: "যদি সাধারণ লুপে Python, C++-এর তুলনায় ৩০ থেকে ১০০ গুণ ধীরগতির হয়, তাহলে বিশ্বের প্রায় সব ফ্রন্টিয়ার AI/ML রিসার্চ কেন Python-এ চলে?"

উত্তর হলো Two-Language Architecture: AI/ML-এ ভারী ম্যাট্রিক্স গণনা আসলে Python করে না। Python কাজ করে একটি অত্যন্ত পরিষ্কার Orchestration ও Control Plane হিসেবে, যা নিচ থেকে কম্পাইল করা C, C++, CUDA এবং Triton কার্নেলকে কল করে (যেমন NumPy, PyTorch, JAX)।

তোমার C/C++ নলেজ এখানে কেন বিরাট সুবিধা: C-তে int32_t x = 42; লিখলে স্ট্যাকে সরাসরি ৪ বাইট ডেটা বসে। কিন্তু CPython-এ x = 42 লিখলে প্রতিটি সামান্য ইন্টিজারও হিপে একটি সম্পূর্ণ C স্ট্রাক্ট (PyObject) হিসেবে তৈরি হয়—যাতে রেফারেন্স কাউন্ট, টাইপ পয়েন্টার ও মেটাডেটা থাকে (ন্যূনতম ~২৮ বাইট!)।
চিত্র ১: কেন সাধারণ Python লুপ স্লো হয় এবং মডিউল ০.২-এ NumPy-এর C-বাফার কেন ১০০ গুণ স্পিড দেয়।
অধ্যায় ০.১.২ • জিরো-স্কিপ মূল রিভিশন

২. মূল Python সিনট্যাক্স ও সূক্ষ্ম আচরণগত পার্থক্য (C/C++ → Python)

তুমি আগে থেকেই C/C++/Java থেকে লুপ, কন্ডিশন আর ফাংশন জানো। তাই অযথা if কী তা নিয়ে পাতার পর পাতা নষ্ট না করে, সরাসরি দেখে নিই কোথায় C/C++-এর অভ্যাস Python-এ নীরব বাগ তৈরি করতে পারে।

বিষয় C / C++ আচরণ Python 3 আচরণ (মন দিয়ে দেখো!)
ভাগ / বনাম // 5 / 2 == 2 (শূন্যের দিকে কাটে: -5 / 2 == -2) 5 / 2 == 2.5 (সবসময় float!)। ফ্লোর ডিভিশন // −∞-এর দিকে নিচে নামে: -5 // 2 == -3!
ঋণাত্মক সংখ্যার % -5 % 2 == -1 (ভাজ্যের চিহ্ন রাখে) -5 % 2 == 1 (ভাজকের চিহ্ন রাখে এবং সবসময় a == (a // b)*b + (a % b) মানে)।
অসীম প্রিসিশন int int64_t ওভারফ্লো করে (signed C-তে UB!) Python-এর int-এর কোনো সীমা নেই (কিন্তু NumPy ফিক্সড-বিট int-এ ওভারফ্লো হয়!)।
is বনাম == == ভ্যালু বা পয়েন্টার ঠিকানা তুলনা করে == মান তুলনা করে (__eq__)। is মেমরি ঠিকানা (id(a) == id(b)) তুলনা করে। সবসময় x is None লিখবে—কখনোই সংখ্যা বা স্ট্রিংয়ের জন্য is নয়!
Truthiness 0 বা NULL মিথ্যা, বাকি সব সত্য False, None, 0, 0.0, "", [], (), {}, set() falsy। সতর্কতা: 0.0 যদি বৈধ ফিচার বা লার্নিং রেট হয়, তবে if x: নয়—সবসময় if x is not None: লিখবে!
ব্লক ও স্কোপ { ... } আলাদা ব্লক স্কোপ বানায় ৪-স্পেস ইন্ডেন্টেশন। if বা for-এর আলাদা ব্লক স্কোপ নেই—স্কোপ কেবল Function, Class এবং Module লেভেলে (LEGB নিয়ম)। লুপের পর লুপ ভেরিয়েবল টিকে থাকে।
Unpacking ও লুপ ম্যানুয়াল ইনডেক্স লুপ for (int i=0; i<n; ++i) সবসময় enumerate(xs) এবং zip(X, Y, strict=True) ব্যবহার করো। স্টার আনপ্যাকিং: first, *middle, last = seq। 
# আধুনিক ও পরিষ্কার Pythonic স্টাইল (প্রতিদিন ML কোডে কাজে লাগবে)
features = [0.2, 0.8, -0.5]
labels   = [0,   1,   0]

for idx, (x, y) in enumerate(zip(features, labels, strict=True)):
    print(f"sample={idx:02d} | x={x:+.2f} | y={y}")

prob = 0.73
assert 0.0 <= prob <= 1.0
অধ্যায় ০.১.৩ • নীরব ML বাগের ১ নম্বর উৎস

৩. Python-এর অবজেক্ট ও রেফারেন্স মডেল (Aliasing বনাম Shallow বনাম Deep Copy)

C++-এ std::vector<int> b = a; লিখলে ভেক্টরটি কপি হয়। কিন্তু Python-এ b = a লিখলে কখনোই ডেটা কপি হয় না! Python-এর ভেরিয়েবল কোনো মেমরি বক্স নয়, বরং হিপে থাকা অবজেক্টের গায়ে লাগানো নেম ট্যাগ (পয়েন্টার)।

  • Immutable টাইপ: int, float, bool, str, tuple, frozenset। এখানে x += 1 করলে নতুন অবজেক্ট তৈরি হয়—অন্য কোনো ভেরিয়েবল নষ্ট হয় না।
  • Mutable টাইপ: list, dict, set, কাস্টম অবজেক্ট, NumPy অ্যারে। ইন-প্লেস পরিবর্তন করলে (.append(), a[0] = 9) ওই অবজেক্টে পয়েন্ট করা সব ভেরিয়েবল নীরবে বদলে যায়!
  • Pass-by-Object-Reference: কোনো ফাংশনে ডেটাসেট লিস্ট পাঠালে একই অবজেক্টের রেফারেন্স যায়। ফাংশনের ভেতর ইন-প্লেস নরমালাইজ করলে বাইরের মূল ডেটাসেটও নীরবে বদলে যাবে!
চিত্র ২: 2D ডেটাসেটে list(data) বা data[:] দিয়ে শ্যালো কপি করা Python ML পাইপলাইনের অন্যতম বড় নীরব বাগ।

ইন্টারেক্টিভ সিমুলেটর: Reference Aliasing এবং [[0]*3]*3 ফাঁদ নিজ চোখে দেখো

অধ্যায় ০.১.৪ • অ্যালগরিদম ও কমপ্লেক্সিটি

৪. মূল ডেটা স্ট্রাকচার, Slicing এবং Comprehensions

যেহেতু তোমার DSA ভালো জানা আছে, তাই Python-এর বিল্ট-ইন কন্টেইনারগুলোকে সরাসরি তাদের ভেতরের C ইমপ্লিমেন্টেশন ও Big-O কমপ্লেক্সিটির সাথে মিলিয়ে নাও:

টাইপ ভেতরের গঠন মূল টাইম কমপ্লেক্সিটি ML-এ প্রধান ব্যবহার
list PyObject* পয়েন্টারের ডায়নামিক অ্যারে ইনডেক্স O(1), append/pop() amortized O(1), pop(0) বা x in list O(n) ব্যাচ তালিকা, লস হিস্ট্রি, ক্রমানুসারে ডেটা
tuple অপরিবর্তনীয় (Immutable) ফিক্সড পয়েন্টার অ্যারে ইনডেক্স O(1), হ্যাশেবল টেনসর শেপ (batch, seq, dim), ডিক্ট কী, একাধিক রিটার্ন ভ্যালু
dict কম্প্যাক্ট হ্যাশ টেবিল (Py 3.7 থেকে অর্ডার সংরক্ষণ করে) সার্চ/ইনসার্ট/ডিলিট গড়ে O(1) টোকেনাইজার ভোকাব token -> id, হাইপারপ্যারামিটার কনফিগ, state_dict
set হ্যাশ টেবিল (শুধু কী) মেম্বারশিপ x in s গড়ে O(1) ডুপ্লিকেট বাদ দেওয়া, ট্রেন/টেস্ট ওভারল্যাপ লিকেজ দ্রুত চেক করা!
নীরব পারফরম্যান্স কিলার: ১ লাখ স্যাম্পলের লুপের ভেতরে if sample_id in train_ids: লিখলে train_ids যদি list হয় তবে সময় লাগবে O(N²) (মিনিটের পর মিনিট হ্যাং হবে!), আর set হলে লাগবে O(N) (মাত্র কয়েক মিলিসেকেন্ড!)।

Slicing ও Comprehensions

# স্লাইসিং: seq[start : stop : step] (stop বাদ থাকে; সবসময় নতুন শ্যালো লিস্ট দেয়)
nums = [10, 20, 30, 40, 50]
nums[-1]       # 50 (শেষ উপাদান)
nums[1:4]      # [20, 30, 40]
nums[::-1]     # [50, 40, 30, 20, 10] (উল্টো কপি)

# List ও Dict Comprehension

W_safe   = [[0.0 for _ in range(3)] for _ in range(3)]         # ৩টি সম্পূর্ণ আলাদা রো!
অধ্যায় ০.১.৫ • ফাংশন ও সূক্ষ্ম ফাঁদ

৫. ফাংশন, *args/**kwargs, মিউটেবল ডিফল্ট এবং Late-Binding Closures

Python ফাংশনের দুটি ক্লাসিক ফাঁদ অনেক অভিজ্ঞ C++/Java ডেভেলপারের ML এক্সপেরিমেন্টকেও নীরবে নষ্ট করে দেয়:

ফাঁদ ক: মিউটেবল ডিফল্ট আর্গুমেন্ট (def হওয়ার সময় মাত্র একবার তৈরি হয়!)

# বাগযুক্ত কোড: লিস্ট [] কেবল ফাংশন ডিফাইন হওয়ার সময় একবার তৈরি হয়, প্রতি কলে নয়!
def log_loss(val, history=[]):
    history.append(val)
    return history

run1 = log_loss(0.9)   # [0.9]
run2 = log_loss(0.4)   # [0.9, 0.4] <-- Run 1-এর ডেটা Run 2-এ ঢুকে পড়েছে!

# সঠিক নিয়ম: সবসময় None ব্যবহার করো
def log_loss_safe(val: float, history: list[float] | None = None) -> list[float]:
    if history is None:
        history = []
    history.append(val)
    return history

ফাঁদ খ: লুপের ভেতর Late-Binding Closure

# বাগযুক্ত: প্রতিটি lambda কল হওয়ার সময় `r`-এর শেষ মান (0.001) খুঁজে বের করে!
scalers = [lambda x: x * r for r in [0.1, 0.01, 0.001]]
[f(100) for f in scalers]  # [0.1, 0.1, 0.1] <-- তিনটাই 0.001 নিয়েছে!

# সঠিক: ডিফল্ট আর্গুমেন্ট দিয়ে তখনই মানটি আটকে দাও
scalers_ok = [lambda x, rate=r: x * rate for r in [0.1, 0.01, 0.001]]
[f(100) for f in scalers_ok]  # [10.0, 1.0, 0.1] ✓

৬. Iterators, লেজি Generators (yield) ও Context Managers (with)

মনে রেখো, তোমার ল্যাপটপে RAM আছে ৭.৪ GiB। ৫০ লাখ ট্রেনিং স্যাম্পল একসাথে একটি Python list-এ লোড করতে গেলে OS সাথে সাথে প্রসেস কিল করে দেবে (OOM)। এর সমাধান হলো Generator (যে ফাংশনে yield থাকে): এটি একবারে কেবল একটি ব্যাচ তৈরি করে থেমে থাকে, ফলে মেমরি খরচ হয় O(batch_size)—পুরো ডেটাসেটের O(N) নয়!

চিত্র ৩: কেন বাস্তব ML পাইপলাইন বিশাল লিস্ট না বানিয়ে Generator দিয়ে ডেটা স্ট্রিম করে।
def batch_stream(data, batch_size: int):
    for i in range(0, len(data), batch_size):
        yield data[i : i + batch_size]

৭. OOP ও Dunder Methods — PyTorch এবং Autograd কীভাবে কাজ করে

Python-এ বিশেষ ডাবল-আন্ডারস্কোর (Dunder) মেথডগুলো তোমার ক্লাসকে সরাসরি Python সিনট্যাক্সের সাথে যুক্ত করে (C++-এর অপারেটর ওভারলোডিংয়ের মতো, তবে আরও শক্তিশালী)। PyTorch-এর প্রায় প্রতিটি "জাদুকরী" লাইন আসলে একটি Dunder মেথড কল:

ML / PyTorch কোড Python ভেতরে যে Dunder মেথড কল করে কেন রিসার্চারদের জন্য জরুরি
len(dataset) dataset.__len__() ডেটাসেটে মোট কতটি স্যাম্পল আছে তা DataLoader-কে জানায়।
dataset[i] বা dataset[-1] dataset.__getitem__(i) ইনডেক্স বা স্লাইস দিয়ে প্রয়োজনমতো ডেটা লোড করে।
logits = model(x) model.__call__(x) অবজেক্টকে ফাংশনের মতো কল করতে দেয় (PyTorch এখানে hooks + forward(x) চালায়)।
c = a * b + d a.__mul__(b) তারপর .__add__(d) ঠিক এভাবেই Autograd কম্পিউটেশন গ্রাফ তৈরি করে!
c = 2.0 * a float.__mul__ ব্যর্থ হয়ে a.__rmul__(2.0) কল করে __radd__/__rmul__ না লিখলে 2.0 * tensor দিলে TypeError আসবে!
print(tensor) tensor.__repr__() ডিবাগিংয়ের জন্য শেপ, টাইপ ও মান স্পষ্ট দেখায়।
